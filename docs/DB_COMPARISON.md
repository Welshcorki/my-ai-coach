# 데이터베이스 비교 및 선정 보고서 (Database Strategy)

## 1. 개요
본 문서는 "AI 자기 계발 코치 (Grow)" 서비스의 데이터 영속성 확보 및 향후 AI 기능 확장을 위해 적합한 데이터베이스를 비교 분석하고, 최적의 기술 스택을 선정하기 위해 작성되었습니다.

## 2. 데이터베이스 유형별 비교

| 종류 | 대표 기술 | 특징 (비유) | 장점 | 단점 | 적합한 용도 |
| :--- | :--- | :--- | :--- | :--- | :--- |
| **RDBMS**<br>(관계형) | **PostgreSQL**<br>(Supabase) | **"엑셀 표"**<br>행과 열이 딱딱 맞는 정리의 신 | - 데이터 무결성 및 정합성 보장 (SQL)<br>- 강력한 생태계<br>- **pgvector** 확장으로 벡터 검색 지원 | - 스키마 변경이 유연하지 않음<br>- 초기 설정 필요 | **회원 정보, 로드맵, 채팅 기록**, AI 벡터 검색 통합 |
| **NoSQL**<br>(문서형) | **MongoDB** | **"서류 봉투"**<br>형식 없이 자유롭게 저장 | - 유연한 데이터 구조 (JSON)<br>- 빠른 개발 속도 | - 복잡한 관계(Join) 처리 시 성능 저하<br>- 트랜잭션 관리가 RDBMS보다 복잡 | 로그 데이터, 비정형 콘텐츠, 게임 데이터 |
| **Embedded**<br>(내장형) | **SQLite** | **"개인 수첩"**<br>서버 파일 시스템에 저장 | - 설정 불필요 (Zero config)<br>- 매우 가벼움 | - **Cloud Run과 같은 Stateless 환경에서 데이터 증발 위험**<br>- 동시 접속 처리 한계 | 로컬 테스트, 모바일 앱, 단일 사용자 앱 |
| **Vector**<br>(벡터형) | **Pinecone**<br>**Chroma** | **"의미 지도"**<br>단어의 의미(유사도) 저장 | - AI 의미 기반 검색(Semantic Search) 특화<br>- RAG 구현 필수 요소 | - 일반적인 CRUD(생성/조회)에는 부적합<br>- 별도 구축 시 비용 및 관리 부담 증가 | **AI 챗봇 메모리, 추천 시스템**, 문서 검색 |

## 3. 서비스 적합성 분석 및 선정

### 🏆 선정: Supabase (PostgreSQL)

**선정 이유:**
1.  **올인원 솔루션 (All-in-One):**
    *   기본적인 **RDBMS** 기능을 제공하여 로드맵, 미션, 채팅 데이터를 안정적으로 구조화하여 저장할 수 있습니다.
    *   **pgvector** 확장을 통해 **Vector DB** 역할을 동시에 수행할 수 있어, 향후 PDF 기반 RAG(검색 증강 생성) 기능을 구현할 때 별도의 벡터 DB를 구축할 필요가 없습니다.
2.  **클라우드 네이티브 (Cloud Native):**
    *   Cloud Run과 같은 Serverless 환경에서는 외부 DB가 필수적입니다. Supabase는 관리형 서비스이므로 서버 재시작과 무관하게 데이터가 영구 보존됩니다.
3.  **가성비 및 편의성:**
    *   넉넉한 무료 티어(Free Tier)를 제공하여 초기 개인 프로젝트에 부담이 없습니다.
    *   직관적인 대시보드와 **Auth(인증)** 시스템까지 통합되어 있어 개발 생산성이 매우 높습니다.

### 🚀 향후 로드맵과의 궁합
*   **1단계 (인프라):** 로드맵/채팅 데이터 영구 저장 -> **PostgreSQL 활용**
*   **2단계 (기능):** PDF 내용 기반 심층 코칭 (RAG) -> **pgvector 활용**
*   **3단계 (확장):** 사용자 로그인/회원가입 -> **Supabase Auth 활용**

## 4. 결론
현재 사용 중인 임시 SQLite(`app.db`)를 **Supabase**로 마이그레이션하는 것이 데이터 안정성과 미래 확장성을 모두 잡는 최선의 선택입니다.
